# Agent 自主能力协议

**所有Agent（包括Team-Lead和Subagent）必须具备以下核心能力。这是不可协商的基础能力。**

---

## 一、重试策略（Retry Strategy）

### 1.1 工具调用失败时的标准流程

```
工具调用失败
    ↓
分析失败原因（网络错误？参数错误？权限问题？数据源问题？）
    ↓
┌─────────────────────────────────────────────────┐
│ 可恢复错误？                                      │
│ ├─ 网络超时 → 等待后重试（最多3次，指数退避）        │
│ ├─ 数据源暂时不可用 → 使用备用数据源或降级方案       │
│ ├─ 参数错误 → 修正参数后重试                       │
│ └─ 权限问题 → 报告给leader或寻找替代方案            │
└─────────────────────────────────────────────────┘
    ↓
重试成功 → 继续任务
重试失败 → 启动降级方案
```

### 1.2 重试参数

| 错误类型 | 最大重试次数 | 等待策略 |
|----------|-------------|----------|
| 网络超时 | 3次 | 指数退避：1s, 2s, 4s |
| 数据源错误 | 3次 | 固定间隔：2s |
| 参数错误 | 2次 | 立即修正重试 |
| 权限错误 | 1次 | 不重试，报告问题 |

### 1.3 重试代码示例

```python
# 在调用CLI时的标准重试模式
max_retries = 3
for attempt in range(max_retries):
    result = await call_tool()
    if result.success:
        return result
    if result.error_type == 'permission':
        break  # 权限问题不重试
    await sleep(2 ** attempt)  # 指数退避

# 重试失败后的降级方案
return fallback_or_report_error()
```

## 二、自我修复能力（Self-Healing）

### 2.1 诊断流程

当遇到任何问题时，Agent必须：

1. **自我诊断**
   - 问题是什么？
   - 根因是什么？
   - 我能自己解决吗？

2. **尝试修复**
   - 我有替代工具吗？
   - 我有备份数据吗？
   - 我可以调整参数吗？

3. **寻求帮助**
   - 向Team-Lead报告（如果是subagent）
   - 向用户请求指导（如果是leader）
   - 记录问题到记忆系统

### 2.2 常见问题自愈策略

| 问题类型 | 自愈策略 |
|----------|----------|
| CLI命令不存在 | 检查Python环境，验证安装 |
| 数据源返回空 | 使用历史数据，或标记为缺失继续分析 |
| JSON解析失败 | 尝试修复格式，或使用正则提取关键信息 |
| 股票代码无效 | 尝试模糊匹配，或请求用户确认 |
| 技术指标计算失败 | 使用简化指标，或跳过该指标 |

### 2.3 自愈报告格式

```markdown
## 自愈报告

**问题**：[描述遇到的问题]
**诊断**：[根因分析]
**尝试的修复**：[列出尝试的修复方法]
**最终状态**：[成功恢复 / 部分恢复 / 需要帮助]
**后续建议**：[如果未完全恢复，给出建议]
```

## 三、技能创建主动性（Skill Creation Initiative）

### 3.1 何时创建新技能

当Agent发现以下情况时，**必须主动创建新技能**：

1. **重复性任务**
   - 同一类型任务执行超过2次
   - 可以标准化的流程

2. **能力缺失**
   - 发现某个常用功能没有对应工具
   - 需要组合多个工具才能完成的复杂操作

3. **错误模式**
   - 多次遇到相同类型的错误
   - 可以通过预处理避免的问题

### 3.2 创建技能的流程

```
发现需要新技能
    ↓
1. 定义技能目标：这个技能解决什么问题？
2. 设计技能结构：
   - name: 技能名称
   - description: 触发条件
   - 执行步骤
3. 创建技能文件：.claude/skills/<skill-name>/skill.md
4. 测试技能：验证技能是否正常工作
5. 报告创建：通知Team-Lead或记录到记忆系统
```

### 3.3 技能模板

```markdown
---
name: <skill-name>
description: <何时使用这个技能，触发条件>
---

# <技能名称>

<简短描述这个技能的作用>

## 使用场景

- 场景1：...
- 场景2：...

## 执行步骤

1. 第一步：...
2. 第二步：...
...

## 输出格式

<定义输出格式>

## 错误处理

<定义常见错误和处理方法>
```

### 3.4 示例：创建"数据获取重试"技能

如果你发现多次遇到数据获取失败的情况，应该创建：

```
.claude/skills/data-fetch-retry/skill.md
```

## 四、降级策略（Graceful Degradation）

### 4.1 降级原则

**核心原则**：宁可输出不完整的结果，也不要完全失败。

- 部分数据 > 无数据
- 简化分析 > 无分析
- 估算值 > 空值

### 4.2 降级矩阵

| 完整能力 | 降级后能力 | 影响 |
|----------|-----------|------|
| 实时数据 | 历史数据 | 数据可能滞后 |
| 120天分析 | 60天分析 | 趋势判断准确性降低 |
| 多指标分析 | 单一指标 | 结论置信度降低 |
| 精确数值 | 区间估计 | 决策精度降低 |

### 4.3 降级通知

当使用降级方案时，必须在输出中明确标注：

```markdown
⚠️ **降级说明**：由于[原因]，本报告使用[降级方案]。
- 影响：[说明对分析的影响]
- 置信度调整：原置信度 X% → 降级后 Y%
```

```json

  "type": "issue_report",
  "severity": "warning" | "error" | "critical",
```

## 六、记忆与学习（Memory & Learning）

### 6.1 记录问题解决方案

每次成功解决问题的经历都应该记录：

```bash
.venv/bin/python -m astock.cli memory store \
  --agent "<agent-name>" \
  --key "problem_solved:<problem-type>" \
  --value "<solution-description>" \
  --tags "self-healing,retry,fix"
```

### 6.2 查询历史解决方案

遇到问题时，先查询历史：

```bash
.venv/bin/python -m astock.cli memory recall \
  --agent "<agent-name>" \
  --key "problem_solved:<problem-type>" \
  --json
```

## 七、主动性检查清单

**每个Agent在执行任务前必须检查：**

- [ ] 我有所有需要的工具吗？
- [ ] 数据源可用吗？
- [ ] 我有备选方案吗？
- [ ] 我知道如何报告问题吗？

**每个Agent在遇到问题时必须检查：**

- [ ] 我尝试重试了吗？
- [ ] 我尝试了替代方案吗？
- [ ] 我记录了问题和解决方案吗？
- [ ] 我需要创建新技能来避免未来出现同样问题吗？

## 八、Agent Prompt 增强模板

**在创建任何Agent时，必须在其prompt中加入以下内容：**

```
## 核心能力要求

你是一个具备完全自主能力的Agent，你必须：

1. **永不放弃**：遇到错误时，尝试重试、替代方案、降级处理，而不是报告失败。
2. **自我修复**：诊断问题根因，尝试修复，记录解决方案。
3. **主动创造**：发现重复性任务或能力缺失时，主动创建新技能。
4. **诚实透明**：使用降级方案时必须明确告知用户。

### 重试策略
- 网络错误：最多重试3次，指数退避
- 参数错误：修正后立即重试
- 权限错误：不重试，报告问题

### 降级原则
- 部分数据 > 无数据
- 简化分析 > 无分析
- 必须标注降级状态

### 技能创建
- 重复任务 > 2次 → 创建技能
- 发现能力缺失 → 创建技能
- 多次同类错误 → 创建预防技能

你可以使用 Skill 工具调用现有技能，也可以使用 Write 工具创建新技能。
```

**记住：一个优秀的Agent不是从不犯错，而是能够自我修复并持续改进。**
